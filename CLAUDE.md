# Parallax — Project Overview

> Last updated: May 4, 2026

## What this is

**Parallax** is a solo YouTube channel analyzing contemporary geopolitics through historical analogy and philosophical frameworks. Created by Tiger (senior data scientist, Math + Philosophy from NYU). AI-assisted research and production pipeline, human narration and editorial judgment.

**Current status:** Pre-launch. Launch candidate is "The Prisoner's Dilemma Is Wrong About Almost Everything" (slug: `prisoners-dilemma`). "The Silicon Trap" (`silicon-trap`) has a finalized production script (v5) and full visual pipeline built but is now queued as a non-launch episode. Project uses a draft/slug-based system — episode numbers are only assigned at publish time. No episodes published yet.

## Key relationships between files

- **palette.json** (`tools/brand-treatment/palette.json`) is the single source of truth for all brand colors. To change a color: edit palette.json → regenerate LUTs (`python treat_video.py --all-luts -o luts/`) → done. All consumers read from it: `theme.ts` (imports JSON directly), `treat.py` and `treat_video.py` (via `palette_loader.py`), `check.py` (via `palette_loader.py`). **BRAND.md** remains the human-readable design spec for colors, typography, and visual treatment, but the machine-readable source is palette.json. `BrandImage.tsx` uses SVG filters derived from `theme.ts`. Pre-generated `.cube` LUT files in `tools/brand-treatment/luts/` can be imported into DaVinci Resolve / Premiere Pro / Final Cut Pro.
- **SCRIPT_FORMAT.md** defines the two-column format with visual mode tags (`[FOOTAGE:]`, `[MG:]`, `[LAYERED:]`, `[AI-GEN:]`, `[ILLUST:]`). `script-v4-production.md` is the working example. The right column feeds `visual-spec` (for Remotion JSON + Recraft illustration specs + footage manifest + AI video briefs), `source.py` (for stock footage), `recraft.py` (for atmospheric illustrations), and `generate_manifest.py` (for assembly manifest).
- **VISUAL_LANGUAGE.md** is the editorial guide for *when* to use footage vs. MG vs. layered vs. AI-GEN vs. atmospheric illustration. It defines the three-register visual system (Analytical/Atmospheric/Grounding), five visual mode tags, pacing rules (max 3 consecutive MGs, max 30s footage, max 2 consecutive AI-GEN or ILLUST), the decision heuristic, register transition grammar (color-wash, blur-through, iris, dissolve), faceless figure convention, and the visual-narrative timing framework (visual-first, synchronized, counterpoint). Also covers visual motifs and the radio edit test. Script writers and script-audit consult this.
- **AI_VIDEO_PIPELINE.md** is the complete specification for AI-generated video — the fourth visual mode. Covers the "stylized realism" aesthetic (realistic environments, mannequin faces), tool selection (Kling 3.0 primary, Sora 2 secondary, Runway Gen-4 tertiary), generation workflow (reference frame → animate → brand treatment → NLE), prompting patterns by use case, editorial guardrails, cost model, and EP01 integration candidates. All AI-GEN clips pass through `treat_video.py` for brand treatment.
- **FOOTAGE_SOURCING.md** is the *where* guide — what footage exists for geopolitics content, organized by sourcability tier (Easy/Moderate/Hard/Unsourceable). Now includes AI-GEN as the primary approach for "Hard" and "Unsourceable" entries that are spatial/physical in nature. Visual-spec and source-feedback skills consult this.
- **DIRECTING_LANGUAGE.md** defines the inline directing vocabulary (`DIR:` annotations) for embedding camera, reveal, timing, and transition direction in the script's right column. Five directive types: `cam()` (camera movement), `reveal()` (element appearance choreography), `hold()` (timing/breathing), `cut()` (transitions), `mood()` (atmosphere). Each maps directly to existing Remotion hook parameters (`useNarratedCamera`, `useCompositionAnimation`, `TransitionWrapper`). Full pipeline integration: **script-draft** emits DIR: lines for P1/P2 moments (~25% of compositions, ~20-35 lines/episode) → **visual-spec** parses them into `_direction` JSON blocks (with camera-system-specific translation: geographic, canvas, scroll, scene-brief) → **audio-spec** reads them for SFX/music decisions (cut()→transition SFX type, hold()→silence moments, mood()→music bed shifts, reveal(sync:)→SFX timestamp placement) → **generate_manifest.py** consumes hold/cut/sync timing (holdAfter, preDelay, narrationGate, transition overrides via Rule 0). Template support matrix shows which directives each template accepts. `useDirection` hook bridges `_direction` JSON to atmosphere/drift/hold values across all 25 templates.
- **PACING_SYSTEM.md** is the timing coordination spec — how narration, camera, and visual density clocks synchronize. Three subsystems: proportional camera paths (rhythm fractions instead of absolute seconds, auto-detected when step durations sum ≤1.01), Whisper sync loop (post-recording WhisperX resolves `syncWords` to frame-accurate `syncPoints`), and visual density budgeting (`PACE:` annotations — urgent/analytical/breathing — control visual change rate via duration multipliers in `generate_manifest.py`). Consumed by `useNarratedCamera.ts` (proportional + sync anchoring), `useDirection.ts` (bridge), `generate_manifest.py` (PACE parsing + Whisper resolution), and all four script skills (draft/audit/visual-spec/audio-spec).
- **AUDIO_DESIGN.md** is the editorial framework for sound design — the audio equivalent of VISUAL_LANGUAGE.md. Defines the 3-layer model (music bed, transition SFX, texture hits), 8 transition cue types, 7 texture hit types, template event → audio cue mappings for all 21+ templates, volume hierarchy, music bed mood mapping, silence as a tool, and assembly manifest extensions. The audio-spec skill reads this before generating cue sheets.
- **Assembly manifest** (`assembly-manifest.json`) is the bridge between script and rendered video. Generated by `tools/assembly/generate_manifest.py`, consumed by `FullEpisode.tsx`. Maps every second to a visual element. Includes per-segment `soundCue` (Layer 2 transition SFX), `soundCueSecondary` (optional second SFX), `textureCues` array (Layer 3 micro-SFX), and root-level `musicBed` object (Layer 1 continuous music tracks with crossfade timing). Direction-aware: parses `DIR:` annotations from script, applies `hold()` timing (holdAfter/preDelay/narrationGate with breathe/land/linger presets), `cut()` transition overrides (Rule 0 priority over default 6-rule system), and `sync` word markers for post-Whisper timestamp alignment.
- **RESEARCH_WORKFLOW.md** documents the Claude.ai Project configurations, custom instructions, prompt templates (including 3-pass research prompts and cross-domain connection hunt), signal monitoring workflow, and the weekly/monthly maintenance cadence. Also defines the competitive landscape check process.
- **IDEAS.md** is the topic pipeline with lifecycle funnel. Topics move through states: Signal Detected → Incubating → Viable → Researching → Research Ready → In Production. Each state has entry/exit gates. Also contains the Signal Watch List (with discovery-path tags: responsive vs. interrogative) for pre-topic pattern tracking, and arc-based organization for episode clusters. Topics are discovered via three entry points in CONTENT_IDENTITY.md: event-first, framework-first, and interrogative (6 systematic question shapes: actor-constraint, mechanism, convergent drift, inversion, conspicuous silence, second-order consequence).
- **PRODUCTION_PIPELINE.md** is the end-to-end map — every stage lists the actual tool, skill, or human action involved.
- **SVG_ILLUSTRATION_PIPELINE.md** covers AI-generated illustrations — when to use SVG vs raster API, prompt engineering, polish audit checklist, and Remotion integration patterns. Companion to IMAGES.md (stock photos) and BRAND.md (design system).
- **DECISIONS.md** is the decision log — 39 decisions with rationale. Check here before proposing something that may already be decided.
- **JIANG_NARRATIVE_RESEARCH.md** is the narrative technique reference. It defines the "decoder, not explainer" posture, 12 extractable techniques, and the toxin-vs-technique line. Referenced by PROJECT_VISION.md (voice profile), EDITORIAL_PLAYBOOK.md (NAR-09 through NAR-13), and the script drafting process. Script-audit should check scripts against the toxin line (NAR-13).
- **EDITORIAL_PLAYBOOK.md** is the compounding knowledge system. It contains channel-level production rules extracted from episode-specific learnings (revision logs, audit reports, analytics). Eight skills read from it before running (research-audit, script-audit, visual-concept, persona-eval, review-package, publish-retro, thumbnail-concept, shorts-adaptation). publish-retro writes back to it after analytics validate or contradict rules. This is the mechanism that makes episode 10 structurally better than episode 1.
- **LEARNING_LOG.md** is the post-publish analytics record. Populated by publish-retro, it tracks persona prediction accuracy, visual type performance, and retention patterns. persona-eval reads it to self-correct predictions; other skills reference it for evidence-based decision-making.
- **Concept Registry** (`data/concepts.json`) tracks every framework, foreign term, named concept, historical analogy, entity, and prediction introduced across episodes. Each entry records the term (bilingual), type, definition, key insight, introduction episode/beat/template/accent color, subsequent appearances, related concepts, content pillars, and a `callbackVisual` field describing the suggested visual treatment for callbacks. The `prediction` type adds fields for claim, probability, timeframe, falsification criteria, status (open/confirmed/falsified/expired/revised), resolution evidence, scenario name, and watch signals — enabling the Oracle identity direction and "Was I Right?" episodes. `visual-spec` checks it before generating visuals (Step 1.5) to detect reuse opportunities and suggest callbacks instead of cold intros. `tools/concepts/lookup.py` provides CLI access: `search`, `episode`, `reuse-check --script`, `show`, `graph`, `validate`, `stats`, `tags`, `add`, `predictions`, `predictions-due`, `resolve`. Schema at `data/concept-registry.schema.json`.

```
     →  script-audit (8 lenses incl. decoder posture + connection density + 6 direction checks)
     →  persona-eval (visual-aware)  →  review-package (synthesis + cold-open variants)
     →  Human review (reads one doc, picks opener)  →  title/hook workshop

     →  visual-concept re-validation (quick check)
     →  visual-spec (parses DIR: → _direction JSON + generative prompts)  →  asset sourcing  →  source-feedback (gap analysis)
     →  audio-spec (reads DIR: for SFX/music decisions)
     →  image treatment  →  Remotion render  →  render-qa (composition verification)
     →  generate_manifest.py (consumes DIR: hold/cut/sync timing)
     →  Human narration  →  NLE assembly  →  Publish
     →  shorts-adaptation (3-4 standalone Shorts briefs from full script)
     →  publish-retro (7-14 days post-launch → LEARNING_LOG.md + EDITORIAL_PLAYBOOK.md)

Knowledge feedback loops (skills read before running, publish-retro writes after analytics):
     EDITORIAL_PLAYBOOK.md ←── publish-retro (validates/retires rules from analytics)
            ↓ read by
     research-audit, script-audit, visual-concept, persona-eval, review-package,
     thumbnail-concept, shorts-adaptation
            ↓ flag
     Candidate Rules (proposed in review-package → approved by Tiger → added to playbook)
```
