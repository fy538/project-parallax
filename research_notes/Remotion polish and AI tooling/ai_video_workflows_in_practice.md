# AI video workflows in practice: agents + programmatic video (Remotion and peers), 2025-2026

Research date: 2026-10-10. Tags used below: **[fetched]** = I opened the primary page; **[snippet]** = seen only through a search-result summary, not opened in full, so verify before quoting; **[vendor]** = the source sells a competing or related product. Source text is paraphrased throughout; command names, file names and numeric rule values are reproduced as facts. GitHub star counts are as displayed on 2026-10-10 and are weak evidence of quality.

## 1. What end-to-end workflows have people published for Claude Code / Cursor / Codex + Remotion since the Remotion agent skills launch, and what do the good ones do differently?

### Takeaway
The baseline workflow (install skills, keep Studio open, prompt, scrub, correct in sentences, render) is well documented but is not what the better projects do: those add a storyboard or beat-timeline gate before code, a tokenised scene kit the agent must compose from, a mandatory render-frames-fix loop, and an audio stage. Almost all evidence is self-reported READMEs and blog posts; I found no controlled comparison of workflows.

### Cited Findings

**Launch and official surface**
- Remotion's Agent Skills launched the week of 23 Jan 2026, alongside Vercel's skills.sh launch on 21 Jan; one write-up reports 3,600+ installs by 23 Jan and an unverified ~147K views for Jonny Burger's demo [snippet, secondary] — [aihola, 23 Jan 2026](https://aihola.com/article/remotion-agent-skills-video-creation)
- The official repo now lists 12 skills: remotion-best-practices, -create, -markup, -studio, -render, -maps, -captions, -saas, -interactivity, -docs, -upgrade, -multimedia; 5.0k stars, 554 forks. The README gives no guidance on how an agent should visually verify output [fetched] — [remotion-dev/skills](https://github.com/remotion-dev/skills), [skills directory](https://github.com/remotion-dev/skills/tree/main/skills)
- The Remotion MCP is deprecated. Stated reasons: its information can lag the docs, Remotion pays the token cost, MCP servers are hard to install and agents do not call them reliably, and it overlaps the /remotion-docs skill. Hosted MCP shuts down no earlier than 31 Aug 2026 [fetched] — [Remotion docs: MCP](https://www.remotion.dev/docs/ai/mcp)
- Remotion docs serve Markdown to agents (append .md to a doc URL, or send an Accept: text/markdown header) [fetched] — [Remotion docs: AI](https://www.remotion.dev/docs/ai/)

- On Syntax.fm (18 May 2026), Wes Bos cited Remotion npm installs rising from about 125k/day in Nov-Dec to almost 800k/day; Jonny Burger attributed the surge to the skills release, said the new audience sends broad non-specific prompts, that a big gap remains to a fast iterative workflow, and that he has not found one-prompt-to-video comfortable. He described Studio's props-schema form controls and an in-progress visual-editing idea that writes UI edits back to code, with code remaining the source of truth. He did not discuss stills or agent feedback loops [fetched] — [Syntax.fm ep. 1005 transcript](https://www.syntax.fm/show/1005/programatic-and-skill-based-video-creation-with-remotion/transcript)

- Engr Mejba Ahmed (2 Apr 2026, revised 15 Aug 2026): brief the agent in plain language, scrub in Studio, correct in sentences, render sections and join with FFmpeg. Reports roughly one prompt in five needs a real correction (rushed timing, text colliding with a chart element, font too small at vertical resolution). Records or generates voiceover first and times compositions to measured audio length. Keeps motion conventions in CLAUDE.md. Advises building one template end to end before generalising to props. **Projects that go beyond the baseline**
- Roboto Studio (6 Jul 2026, updated 24 Aug 2026): three layers — a scene kit of primitives, an agent skill (v1.5.0, 13 hard rules) and ADRs 0001-0007. ### Inferences
- The recurring differentiators are (a) a human-reviewed text storyboard or beat map before any code, (b) 3-4 approved style frames/stills before a full build, (c) a kit of primitives plus named tokens so the agent composes rather than hand-rolls, (d) a single timeline file that scenes, audio and review all read, and (e) a hard rule that nothing ships without frame inspection.
- The reader's stack (≈90 templates, Zod schemas, assembly manifest, registers and lints) already covers (c) and (d) more rigorously than any project found. The deltas worth considering are narrower: a beat-indexed contact sheet generated from the manifest, deterministic geometry checks (section 2), an audio cue sheet with a loudness gate (section 7), trigger-style skill descriptions, and ADR-style final rulings to stop re-litigation.
- Several projects moved or forked toward HyperFrames in mid-2026; that reflects agent ergonomics for greenfield work (plain HTML, built-in check command), not evidence that output quality is better.

- No YouTube walkthrough was opened; none is cited.
- Remotion's own launch post and Jonny Burger's launch thread were not retrieved; launch details rest on secondary coverage.
- No published before/after or controlled comparison of any of these workflows.

## 2. How do people close the visual feedback loop for an agent, what evidence exists that these loops improve results, and what are the failure modes?

### Takeaway
Practitioners converge on stills and contact sheets (one frame per beat; first/middle/last per shot), dense frame strips for a single motion, and deterministic checks (overflow, text collision, contrast, one-frame pops, loudness). Research shows visual critique loops help when structured (separate critics, one repair target per round, 1-3 rounds, history of past repairs) and can make output worse when run naively, at 10x or more the token cost.

### Cited Findings

**What agents can see**
- Claude accepts images but not video; for animated GIFs only the first frame is used. High-resolution tier (Claude 4.7 and later) caps at 2576px long edge / 4784 visual tokens; a 1920x1080 still is not resized and costs 2691 tokens; a 3840x2160 image is downscaled to 2576x1449. Requests with more than 20 images apply a stricter per-image limit (resize so neither side exceeds 2000px). Docs warn about hallucination on very small images (<200px) and that resizing can make text illegible; they recommend labelling multiple images (Image 1:, Image 2:) and putting images before text [fetched] — [Anthropic vision docs](https://platform.claude.com/docs/en/build-with-claude/vision)

**Practitioner techniques**
- claude-motion: `npm run sheet -- --video <mp4>` yields one timestamped frame per beat; `--from 3 --to 5 --every 0.2` scrubs a transition. The agent checks collisions, clipping, holds, safe area and phone readability [fetched] — [claude-motion](https://github.com/whaleyxbt/claude-motion)
- ClaudeAnimationBase: contact sheets show first, middle and last frame of each shot; strips show every frame of one motion and are presented as the only way to catch a pop or missing anticipation; full-resolution crops for story-critical faces. Pixel statistics catch blank frames but not semantic failures. A reviewer once scored a frame 4/10 that was still a placeholder. Re-rendering does not cost model tokens; attaching sheets does [fetched] — [explainx.ai](https://explainx.ai/blog/how-opus-5-5-viral-videos-are-made-code-not-diffusion-2026)
- claude-remotion-skill: render, extract frames with ffmpeg, inspect, fix, re-render; which and how many frames is unspecified [fetched] — [claude-remotion-skill](https://github.com/haidrrrry/claude-remotion-skill)
- brand-motion-design: stills at every handoff with measured boxes and safe zones in a debug mode; HyperFrames check for text crossing text, contrast and overflow; draft render; contact sheet; a verify script for duration, BT.709 tags, colours, loudness and true peak [fetched] — [brand-motion-design-skill](https://github.com/ouerf-man/brand-motion-design-skill)
- claude-motion-design: 540p draft before master; contact sheet; automated pop / one-frame flash detection; loop-seam check in position and velocity; side-by-side compare sheets against a reference in remake mode [fetched] — [claude-motion-design](https://github.com/howseen-ai/claude-motion-design)
- HyperFrames `check` (v0.7.50 notes): one browser session runs lint, runtime errors, layout, motion-intent assertions from *.motion.json, and WCAG contrast; findings carry source anchors, annotated frames and per-finding crops; `snapshot --zoom` gives high-density crops; persistent findings fail the exit code while transient entrance/exit findings are informational. Older docs: contrast sampled at 5 timestamps with 4.5:1 / 3:1 thresholds; layout audit reports overflow, off-frame elements and occluded text per timestamp [snippet, third-party mirrors] — [release notes v0.7.50](https://newreleases.io/project/github/heygen-com/hyperframes/release/v0.7.50), [hyperframes-cli skill](https://tessl.io/registry/skills/github/heygen-com/hyperframes/hyperframes-cli)
- remotion-superpowers delegates review to a video-native model (TwelveLabs) rather than stills [fetched] — [remotion-superpowers](https://github.com/dojocodinglabs/remotion-superpowers)
- Browser-driven Studio review via claude-in-chrome is reported by one developer [snippet] — [X post](https://x.com/omarsar0/status/2021222728393687217)

**Evidence that loops help**
- Amazon, Vision-Guided Iterative Refinement (7 Apr 2026): render HTML, screenshot, VLM visual critic (Claude 4.5 Sonnet), code critic, improver, 3 cycles. Sonnet 4.5 generator: 7.584 initial, 7.958 / 8.021 / 8.048 after cycles 1-3; best-per-task 8.402 (+10.8%). Most gain arrives in cycle 1. Refining without a critic gave +1.5%. Tokens rose from ~6.4k to ~73k for Sonnet's best-of-run. Code quality declined slightly across cycles. A multi-dimensional judge agreed with human preference 69.5% vs 48.5% for a single-score judge. Best numbers use the same judge for selection and reporting, so are optimistic [fetched] — [arXiv 2604.05839](https://arxiv.org/html/2604.05839v1)
- OmniManim (15 May 2026): argues layout and overlap defects cannot be reliably found from code alone. On EduRequire-500 with GPT-5.4: overlap score 0.763 vs 0.628, layout quality 0.931 vs 0.778, animation continuity 0.802 vs 0.764. Removing the vision agent caused the largest drop. Repair is limited to one round. Human study (60 tasks, 20 raters): 81.0 vs 76.0 for GPT-5.4 alone (p=0.009) and 68.4 for Code2Video. An interpolation-aware loss penalises objects that look fine at keyframes but collide at intermediate times (u = 0.25, 0.5, 0.75) [fetched] — [arXiv 2605.15585](https://arxiv.org/html/2605.15585)
- METAL (ACL 2025): multi-agent chart generation with separate visual and code critics; +5.2% over prior best, and the separate-critique design beat a single-critique baseline by 5.6% [snippet] — [arXiv 2502.17651](https://arxiv.org/html/2502.17651)
- Animation2Code (26 Jun 2026): dual-critic iterative refinement improved appearance +4.4% and temporal +9.0% on the first iteration, +0.9% and +3.0% by the third [fetched] — [arXiv 2606.28593](https://arxiv.org/html/2606.28593)
- Code2Video (Oct 2025; NeurIPS 2025 DL4C workshop): planner, coder, and a VLM critic using visual anchor prompts; reports 40% improvement over direct code generation [snippet] — [showlab/Code2Video](https://github.com/showlab/Code2Video)

**Evidence that loops fail or plateau**
- RubSE (arXiv 2608.24138, UMD + Microsoft): naive critique-then-revise frequently ends below the first draft. On Design2Code all 15 of 15 GPT-5.2 refined rounds landed below round 0 (ending at -2.73); GPT-5.4 gained +0.76 in round 1 then fell to -1.82. Cause: free-form critique says what is wrong without constraining what must stay, so repairs rewrite broadly. Fix: typed rubric items across five aspects (layout geometry, spacing density, typography, styling, completeness), select exactly one repair target per round, keep a history/avoid-list. Result: +1.20 average at round 10, collapse rate 18.9% to 12.8%, at 1.60x the API cost of the naive loop; feeding back the full candidate set recreated the broad-edit problem. Project page, not yet peer reviewed [fetched] — [RubSE](https://tyxiong23.github.io/rubse)
- Design2Code (2024): a self-revision prompt showing reference, render and code brought no improvement for GPT-4V and Claude 3 [snippet] — [arXiv 2403.03163](https://arxiv.org/pdf/2403.03163)
- AUV-Bench (28 Sep 2026): a correct diagnosis improved repair by +8.7 to +24.2 points, but for Kimi-K3 an incorrect diagnosis cut repair by 17.5 points; the best full diagnosis-chain success was 24.7%; a Claude Code harness did not consistently improve generation scores (stayed near 3.0 of 5) [fetched] — [arXiv 2609.34854](https://arxiv.org/html/2609.34854)
- HeyGen (18 Sep 2026) [vendor]: says skills and multi-agent review improve output but add token cost and engineering overhead and act as a ceiling rather than a fix [fetched] — [HeyGen Code2Video benchmark](https://www.heygen.com/research/introducing-code2video-benchmark)
- TheoremExplainAgent (Feb 2025) reports most generated Manim videos still show minor layout issues; a 2026 physics-video paper using a screenshot loop reports problems in how the VLM interprets images during feedback [snippet] — [arXiv 2502.19400](https://arxiv.org/abs/2502.19400), [arXiv 2601.13453](https://arxiv.org/pdf/2601.13453)

### Inferences
- Contact-sheet arithmetic (my calculation from the Anthropic limits): a 4x4 sheet of 1080p frames is downscaled to 2576x1449, so each tile is about 644x362 — roughly one-third linear scale; a 3x3 gives ~858x483; a 2x2 gives ~1288x724. Sheets are therefore suitable for sequence, composition and collision checks, not for typography or fine spacing. Typography and hierarchy checks should use full-resolution single stills (1920x1080 passes unscaled on the high-res tier) or crops.
- GIF or MP4 previews are useless to Claude directly; frames must be extracted. A video-native reviewer (TwelveLabs, Gemini) is the only way to send actual video, and section 3 shows that does not solve motion judgment.
- The most defensible division of labour: deterministic checks for geometry (overflow, off-frame, text-text overlap, contrast, one-frame pops, mid-travel collisions sampled at intermediate times); VLM for semantic and hierarchy questions on full-res stills; the human for taste and direction.
- Loop design supported by the evidence: cap at 1-2 automated rounds; one repair target per round; state what must not change; keep a per-scene repair history; use separate critic and fixer contexts; do not let the same judge both select and report.
- Since Remotion renders in headless Chrome, the DOM measurements HyperFrames performs are technically feasible for Remotion templates, but I found no published Remotion-native equivalent.

### Gaps
- No measurement of feedback loops specifically on Remotion video output.
- False-positive rates of VLM visual critics are not quantified in the papers read.
- No published account of pixel-diff/screenshot-regression loops driven by an agent for video.
- No evidence beyond one anecdote for driving Remotion Studio through a browser or MCP; the official Remotion MCP was documentation-only and is deprecated.
- The official HyperFrames docs site was not reached; check details come from mirrors and release-note aggregators.

## 3. How well do multimodal LLMs judge design and motion quality, which techniques make judgments more reliable, and can models judge motion from frame sequences?

### Takeaway
For static design, frontier models correlate moderately with designers (Spearman about 0.5-0.57), rank better than they score, localise poorly, and write generic all-aspects critiques. For motion, 2026 benchmarks consistently show models cannot reliably perceive speed, timing or easing from frames or native video, and denser sampling barely helps (plateau around 16-24 frames); purpose-built automatic metrics outperform VLM judges.

### Cited Findings

**Static design and aesthetics**
- AUV-Bench (28 Sep 2026; 1,395 web UIs, 44 designers): aesthetic-scoring SRCC for frontier models 0.50-0.57 (Claude Opus 5: 0.56, MAE 0.81 on a 1-5 scale); degraded-version detection 91.1% balanced accuracy for Claude Opus 5 but region localisation F1@0.5 only 36.7. Two Qwen models left the overall score unchanged on 83.5% and 86.4% of degraded samples [fetched] — [arXiv 2609.34854](https://arxiv.org/html/2609.34854)
- MLLM as a UI Judge (Oct 2025; 30 UIs, ~500 crowdworkers): mean scores close to human (human 6.10, Claude 6.08, GPT-4o 5.75), MAE under one point on most factors; pairwise accuracy peaks around 75% [snippet] — [alphaXiv 2510.08783](https://www.alphaxiv.org/overview/2510.08783)
- VLM Judges Can Rank but Cannot Score (28 Apr 2026): 32-34% exact agreement with humans on a 5-point scale, 70-76% within one point, Pearson 0.30-0.46; judges overscore poor work and underscore excellent work; uncertainty intervals 4.5x narrower when ground truth is multi-annotator. Recommends relative ranking or pairwise comparison where intervals are wide [fetched] — [arXiv 2604.25235](https://arxiv.org/html/2604.25235v1)
- Pairwise vs absolute is contested: GenArena (2026) finds pairwise more accurate and stable for visual generation; another 2026 paper cites pairwise preferences flipping in ~35% of cases under distractor features versus ~9% for absolute scores, plus position, verbosity and self-enhancement bias [snippet] — [arXiv 2602.06013](https://arxiv.org/pdf/2602.06013), [arXiv 2603.04325](https://arxiv.org/pdf/2603.04325)
- A multi-dimensional judge agreed with human preference 69.5% vs 48.5% for a single overall score, and draws fell from 28.5% to 8.5% [fetched] — [arXiv 2604.05839](https://arxiv.org/html/2604.05839v1)
- Can MLLMs Critique Like Humans? (v2 31 Aug 2026; 1,227 photo-critique posts): models mention composition in over 97% of critiques vs 48.2% for humans; critiques are roughly twice human length; judges disagree wildly (GPT-4o preferred one model's critique in 73% of pairs, Claude Opus 5 in 11%); image grounding contributes little versus text context. Aspect hints did not narrow coverage; asking for three critiques in one pass was the only format that restored selectivity [fetched] — [arXiv 2606.29689](https://arxiv.org/html/2606.29689)
- UICrit (UIST 2024) reports few-shot + visual prompting improved LLM UI feedback by 55%; the follow-up adds iterative refinement with a magnified crop of each candidate region, roughly tripling box IoU over zero-shot, and notes GPT-4o refinement without few-shot examples adjusted nothing. Later work still finds human designer critiques stronger than all LLM methods [snippet] — [arXiv 2407.08850](https://arxiv.org/pdf/2407.08850), [arXiv 2412.16829](https://arxiv.org/pdf/2412.16829), [PerceptUI, arXiv 2606.05697](https://arxiv.org/html/2606.05697v1)
- Rubric wording matters: RubSE finds typed, action-oriented rubric items phrased as perceptual relations (layout, scale, hierarchy) work better than low-level CSS values, and rubrics from a stronger model transfer to weaker fixers [fetched] — [RubSE](https://tyxiong23.github.io/rubse)

**Motion, timing and easing**
- Animation2Code (UC Berkeley, 26 Jun 2026; 1,069 web animations): models reproduce appearance well (up to 0.84) but temporal similarity is uniformly low (max 0.31). Frame-rate ablation: Gemini native video temporal score 0.295 / 0.315 / 0.321 / 0.309 at 2 / 8 / 16 / 24 FPS; Claude image frames 0.287 at 2 FPS vs 0.294 at 8 FPS; GPT image frames slightly worse with more frames. Native video gives only marginal gains over image frames. Humans agree on temporal quality (Krippendorff alpha 0.73), and at least one automatic metric (DreamSim + DTW for appearance; point-tracking motion fidelity for timing) beats a Gemini-3.1-Pro VLM judge on every dimension [fetched] — [arXiv 2606.28593](https://arxiv.org/html/2606.28593)
- MotionBlind (Northeastern, 8 Sep 2026; 240 contrastive items on speed, magnitude, direction): strict instance accuracy 60.0% for Gemini 3.1 Pro, 15.0% for GPT-5.6 Luna, 3-12% for open models, versus 91.3% for humans; Gemini reaches only about 14% on speed. More frames help until a plateau at 16-24; learned frame selection did not beat uniform sampling [fetched] — [arXiv 2609.09528](https://arxiv.org/html/2609.09528)
- HeyGen Code2Video benchmark (18 Sep 2026) [vendor]: on pairwise preference for agent-made motion-graphics video, general VLMs (Gemini 3.5, GPT-5.5, order-swapped to control position bias) aligned with trained human annotators 75% of the time and were inconsistent; HeyGen's dedicated non-VLM judge reached 82% overall and 98.8% when its confidence was high. It scores five axes separately (engagement, prompt-intent, composition, temporal, craft). Judge architecture is unpublished [fetched] — [HeyGen](https://www.heygen.com/research/introducing-code2video-benchmark)
- NextMotionQA (2026): a VLM judge agrees with experts on coarse criteria (kappa 0.70) but collapses on fine-grained part-level judgment (kappa 0.10); human motion, not graphics [snippet] — [arXiv 2606.04773](https://arxiv.org/abs/2606.04773)
- FPS-Bench (CVPR 2026) introduces a minimum-FPS metric and shows some events are invisible at 2 FPS and visible only at ~14 FPS; MotionBench (Jan 2025) reports fine-grained motion accuracy below 60% even with higher frame rates [snippet] — [FPS-Bench](https://openaccess.thecvf.com/content/CVPR2026/papers/Choudhury_FPS-Bench_A_Benchmark_for_High_Frame-Rate_Video_Understanding_CVPR_2026_paper.pdf), [MotionBench](https://arxiv.org/abs/2501.02955)
- Gemini samples video at 1 FPS by default (~258 tokens per frame at default resolution), supports custom fps via video metadata, and added an agentic video mode in Sep 2026 in which the model chooses segments and fps [snippet, third-party] — [s-anand.net](https://www.s-anand.net/blog/how-does-gemini-process-videos/), [Google AI forum](https://discuss.ai.google.dev/t/set-custom-fps-not-working/85877), [howaiworks.ai](https://howaiworks.ai/blog/google-gemini-agentic-video-2026)
- OmniManim measures animation continuity with lightweight CV metrics (frame differences, centroid jitter, discontinuities, flicker) rather than a VLM, and says these heuristics are not a substitute for expert judgment [fetched] — [arXiv 2605.15585](https://arxiv.org/html/2605.15585)

### Inferences
- Do not ask a VLM whether easing or timing feels right. No source shows current models can do this from filmstrips, and the two most relevant benchmarks show timing perception near floor regardless of sampling density. In a code-based pipeline the motion is known exactly, so judge it numerically: assert the easing token, duration and stagger per element; sample per-frame positions and check velocity continuity; detect one-frame pops by frame differencing.
- Filmstrips are still useful for what models can see: mid-travel collisions, clipping, elements missing or out of order, wrong end states. Practical sampling with no measured optimum: every frame or every second frame across the transition window, kept to roughly 16-24 frames (a 0.5s entrance at 30fps is 15 frames), sent as separate labelled images or a 2x2/3x3 grid rather than one dense sheet.
- For static design, reliability ranks roughly: pairwise against a reference style frame (run both orders) > per-dimension rubric scores > single overall score. Ask for a small fixed number of ranked issues rather than a full critique, to counter the cover-every-aspect bias. Use crops to confirm any localised claim before acting on it.
- Absolute scores (for example 7/10) from a model reviewer should not gate anything; treat them as within plus or minus one point at best.
- A second judge model adds signal only if disagreements are surfaced rather than averaged; evidence shows judges differ systematically.

### Gaps
- No benchmark tests perception of easing curves, hold lengths or pacing in motion graphics specifically; Animation2Code measures reproduction, MotionBlind uses real-world clips.
- No study isolates the effect of anchored example frames, zoomed crops or multi-judge ensembles on design-quality judgments (crop evidence is for localisation only).
- No paper found on chart-design quality judgment by VLMs with measured human agreement; an ACL 2025 industry paper on LVLM chart-comprehension judging exists but concerns answer quality, and I did not open it.
- Whether Gemini's agentic video mode improves motion-quality judgment is untested in sources found.

## 5. What do practitioners say are the most common tells of AI-made Remotion videos, and what rules or checklists do they use to avoid them?

### Takeaway
The tells practitioners name are consistent: linear or uniform easing, lone opacity fades, everything entering at once, no exits, flat backgrounds, static pasted images, undersized safe layouts, text that collides mid-travel, and style drift between scenes. The countermeasures are specific numeric rules plus enforced tokens; none has been validated against viewer perception.

### Cited Findings
- claude-remotion-skill lists default-agent failures as: linear interpolation everywhere, isolated opacity fades, simultaneous entrances, flat solid backgrounds, static pasted images, and shipping unverified renders [fetched] — [claude-remotion-skill](https://github.com/haidrrrry/claude-remotion-skill)
- HeyGen's benchmark failure patterns (frontier models, Sep 2026): linear transitions or abrupt delays instead of eased motion; text laid out for its final position so it collides while travelling; models playing safe by shrinking everything to a fraction of intended scale; headlines pushed to corners or clipped; a typewriter title dropping its last letter; wordmark letters never settling on a baseline; timing between beats breaking even when every beat is present [fetched; vendor] — [HeyGen](https://www.heygen.com/research/introducing-code2video-benchmark)
- Roboto Studio's drift audit (prompting with docs only): inconsistent font sizes for the same role, unscaled gaps, varying tint opacities, one stylistic outlier scene, and five outlier easing curves in ten scenes [fetched] — [Roboto Studio](https://robotostudio.com/blog/how-to-use-remotion-agent-skills-with-claude-code)
- Rescroll's description of a default-looking graphic: a bare number with no container, chart, brand font or exit animation; also graphics landing a beat late [fetched; vendor] — [Rescroll](https://www.rescroll.ai/blog/claude-code-remotion-motion-graphics-2026)
- Mejba's recurring corrections: rushed timing, text/chart collisions, type too small on vertical [fetched] — [mejba.me](https://www.mejba.me/blog/claude-code-remotion-youtube-motion-graphics)
- A reviewer of a Claude-made marketing channel notes identical easing curves, the same background-gradient family and the same logo motion across videos [snippet] — [timewell.jp](https://timewell.jp/en/columns/remotion-claude-code-programmatic-video)
- A debugging guide attributes mechanical feel to `interpolate()` without easing and suggests scrubbing an entrance to see whether speed is constant [snippet] — [dplooy](https://www.dplooy.com/blog/claude-code-video-with-remotion-best-motion-guide-2026)
- One tutorial author says Remotion is weakest exactly where easing must be nudged by eye, which a graph editor does faster [snippet] — [wellstsai](https://wellstsai.com/en/post/remotion-video-animation-tutorial/)
- Concrete numeric rules in circulation: entrances on `bezier(0.16, 1, 0.3, 1)`, exits at half the entrance duration, 0.09s between words (claude-motion); 3-6 frame stagger offsets (claude-remotion-skill); entrance scale starting near 0.95 rather than 0, ease-out for enter/exit, ease-in-out for on-screen moves, linear only for constant motion, exits ~20% faster than entrances, larger elements slower (Emil Kowalski, UI-oriented, undated); max font weight 600 and min font size 28px, 60-30-10 colour rule, easeOutExpo with per-character stagger (norahe0304 skill, archived May 2026); a new picture every 2 beats and under twenty words on screen (brand-motion-design, promo register) [fetched] — [claude-motion](https://github.com/whaleyxbt/claude-motion), [claude-remotion-skill](https://github.com/haidrrrry/claude-remotion-skill), [Emil Kowalski](https://emilkowal.ski/ui/agents-with-taste), [remotion-video-skill](https://github.com/norahe0304-art/remotion-video-skill), [brand-motion-design-skill](https://github.com/ouerf-man/brand-motion-design-skill)
- Storyboard-level gates: every shot has an event, no overlapping key reads, every seam has a transition (ClaudeAnimationBase) [fetched] — [explainx.ai](https://explainx.ai/blog/how-opus-5-5-viral-videos-are-made-code-not-diffusion-2026)
- By analogy from UI work, Anthropic's frontend-design skill is described as countering convergence on statistically common safe choices (Inter, purple gradients, standard grids) by naming and forbidding the defaults and committing to a direction before coding [snippet, third-party descriptions] — [Medium: N. Porter](https://medium.com/@porter.nicholas/anthropic-skills-marketplace-the-anti-ai-slop-ui-design-skill-a572d0cfef4f), [Superdesign](https://www.superdesign.dev/blog/how-to-make-claude-code-ui-look-good) [vendor]
- A 2025 School of Motion roundtable frames taste as the scarce skill as technically clean output becomes cheap; not about Claude or Remotion specifically [snippet] — [School of Motion](https://schoolofmotion.com/blog/eoy2025)

### Inferences
- A consolidated tell list a reviewer (human or lint) can check: (1) any linear tween that is not constant-motion; (2) opacity-only entrances; (3) simultaneous entrances with zero stagger; (4) no exit animation or exits as slow as entrances; (5) elements well below intended scale with large dead margins; (6) collisions or clipping at intermediate frames; (7) more distinct easing curves or durations in an episode than the token set allows; (8) identical motion signature on every scene; (9) flat untextured backgrounds; (10) static images with no motion treatment; (11) holds too short to read; (12) no sound events on visual beats.
- Items 1, 3, 4 and 7 are lintable from template data or source; 5, 6 and 11 are checkable from rendered frames with measurement; 8 is an editorial-variety check at the manifest level.
- The reader's existing registers (text animation, hold motion, transition grammar, pacing) and lints already address most of 1-4, 7-8 and 11. The items least likely to be covered by existing checks are mid-travel collisions (6) and the shrink-to-safe failure (5), both of which the HeyGen benchmark found in the strongest models.
- Numeric rules from UI skills (durations under 300ms) do not transfer to essay video; only the relational rules do (exits faster than entrances, larger moves slower, start scale near 0.95).

- No study of what viewers actually perceive as AI-made in motion graphics.

## 6. Are there published design-system or motion-token approaches for agents, and any results on consistency?

### Takeaway
Yes: several practitioners constrain agents to a small set of named motion roles, timing scales and primitives, and enforce them through a skill plus a component kit. The only consistency result found is one studio's before-audit; there is no controlled measurement that token constraints improve agent output.

### Cited Findings
- Roboto Studio motion roles, named by meaning rather than curve: enter (out-quint, 0.5s), exit (in-cubic, 0.3s), move (in-out-cubic, 0.6s), sweep (linear, rate-based). - claude-remotion-skill enforces a single theme.ts with no inline colours or easings and all timing derived from fps [fetched] — [claude-remotion-skill](https://github.com/haidrrrry/claude-remotion-skill)
- claude-motion keeps every beat as a named timestamp in timeline.json shared by scenes, sound and review [fetched] — [claude-motion](https://github.com/whaleyxbt/claude-motion)

### Inferences
- Schema-enforced enums (as in the reader's Zod-validated direction fields) plus lint rules are a stronger form of motion tokens than the prose-rule skills published by others, because violations fail validation instead of relying on the agent reading a rule.
- Transferable practices not obviously present in a template-plus-register system: name tokens by editorial role rather than by curve; attach a use-when note to each token; run a periodic grep-style drift audit across episode data counting distinct easings, durations and sizes; mark rulings final in an ADR/decision log so the agent stops reopening them.
- Tokens secure consistency and remove the generic defaults; they do not supply direction. Every source that addresses this says choice of direction stays with the human.

- MOTION.md's actual token values and any adoption data were not retrieved.

## 7. What is the state of AI-assisted audio for such pipelines as it affects perceived polish?

### Takeaway
The more careful agent kits treat audio as a first-class, timeline-driven stage: a cue sheet derived from visual beats, SFX placed on exact frames, music cut or generated on a grid, ducking under voice, and a loudness gate (commonly -14 LUFS, true peak under about -2 dBFS). Tooling is mature; evidence that it measurably improves perceived polish was not found.

### Inferences
- The pattern worth copying is structural, not the generators: derive the SFX cue sheet mechanically from the same timeline that drives visuals, place hits on measured frames, and gate the final mix on LUFS and true peak with a script. These are cheap, deterministic and independent of model taste.
- For a human-narrated channel where the script is known, forced alignment against the recorded narration is likely more robust than transcription-based Whisper timing for syncing reveals to words.
- Most published audio stages target beat-driven promo video (music-led cuts, trap beds, risers). For an essay register the transferable pieces are restrained transition and texture hits, consistent loudness, and ducking — not beat-synced cutting.
- Models cannot hear the mix; audio review by the agent is limited to measurements (loudness, peaks, cue-to-frame alignment, overlap counts). Whether it sounds right remains a human check.

- No source documents a sidechain-style ducking implementation inside Remotion; the examples found use fixed gain reduction.
